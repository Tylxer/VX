## 0. 一句话结论
**判据链完全正常，卡点在静音落地**：通知被改到自建静音通道 `wxgroup_silent`，但这个通道现在是**有声有震**的，且声音/重要性字段被用户锁定（app 无法覆盖）。`AT muted` 日志只证明「判据通过 + 两个反射函数返回 true」，不证明手机真的静音。

## 2. 诚实边界（不许越界写成事实）
- ⛔ **通道 `0x26` 是何时、由谁写入的**（用户手改系统设置 / ColorOS 恢复默认 / 系统升级重置）——现有日志与 dumpsys **无法自证**，标 [假设]。它解释「为何纠正可能无效」，不等于「根因已证明」。
- ⛔ **用户实际听感未确认**：01:03 那条答「不确定」。第 8 步是 [推断·高] 不是 [真机实证]，最终要靠一次「用户听感 + 通道字段」两侧对账坐实。
- ⛔ **两处同名通道是代码事实但非现役竞争**：`core/NotifyMute` 安装点在 `HookEntry.kt:319-321` 被注释（2026-10-17 停用 K9），现役只有 `MuteAt`；现场日志前缀 `QUIET` 也佐证。排除「双写竞争」。
- ⛔ `mVibrationEnabled=true` 但 VIBRATION 位（bit4）**未锁** ⇒ 震动开启不是用户锁定，是当前字段值；不要写成「用户锁了震动」。

## 3. 判据设计（对用户可见事实，不靠内部计数器）
### 3.1 最终判据（修后验收用）
- **正向**：发一条 @全体成员 → ①用户确认**未听到铃声/震动**；②dumpsys 该通道 `mSound=null` 且 `mVibrationEnabled=false`；③通知仍在通知栏（静音不是吞通知）。三项**同时**成立才算静音成功。
- **反向（关开关复现）**：`kvset chat.mute_at_enabled=false` → 回读 false → 同群再发 @全体成员 → 用户确认**响铃/震动恢复**。证明静音确由本功能落地、可逆、无持久副作用。
- **互斥声明**：`AT muted`（判据层）与「通道无声」（落地层）**不是同一件事，也不互斥**——两者可同时「真」（日志打了但通道有声）。总判据必须含通道字段 + 用户听感，不能只看任一计数器。
- **判据红线**：`matched/muted/bound` 等内部计数器**一律不作最终判据**（本次教训：`muted=2` 却是假象）。

### 3.2 三组变异验证（针对将来修法的逻辑层单测）
| 变异 | 改法 | 期望 |
|---|---|---|
| M1 | 把「通道静音检查」换成「通道存在检查」 | 必须红（存在≠无声，无法区分有声通道） |
| M2 | 去掉 user-lock 判断，假定 app 覆盖一定生效 | 必须红（SOUND 被锁时覆盖无效，会误判修好） |
| M3 | 把最终判据从通道字段退回 `AT muted` 计数器 | 必须红（回到本次假象） |

⛔ 变异前先确认变异**有语义**（不是等价变异）；0 条红 = 假验证。

## 4. 路线重排（Lite 查证后修订——A 不再是首选）
| 路线 | 核心动作 | 命门 / 失效场景 | 评价 |
|---|---|---|---|
| A 强制纠正通道 | `mute()` 每次 `setSound(null)` 覆盖 | **SOUND 位已被锁，AOSP 忽略 app 覆盖 ⇒ 大概率无效**（原推荐被推翻） | 降级；除非先删通道重建（用户设置突变、OEM 可能拦） |
| **B′ 换新版静音通道 id（新增，首选）** | 新 id（如 `wxgroup_silent_v2`）+ `IMPORTANCE_HIGH` + `setSound(null)`；新通道首次创建无 user lock，参数生效 | 系统设置里多一个通道；用户若再手改新通道会复现（用户行为，无法根治）；需确认 OEM 不会自动重建旧通道覆盖 | **绕开 locked，对症**；保持 HIGH ⇒ 通知照常弹、角标照常 |
| B 换 IMPORTANCE_MIN | 系统保证不响不震 | 通知**不弹横幅**（想看到但不响的场景退化） | 次选 |
| C 只清 Notification 字段 | 不动通道，`notification.sound/vibrate=null` | Android O+ 通道优先级高于对象字段，OEM 可能忽略 | 不推荐 |

**推荐排序：B′ > B > A > C。** B′ 是唯一同时满足「绕开被锁字段 + 保留通知横幅/角标 + 新通道无 user lock」的方案。
