## 二、已写代码但没上真机验（5 项，建议合成一个批次）

> 这五项都已编译通过 + 单测全绿，缺的只是真机跑一遍。可一次装包连续验完。

### 2.1 ⚠️ P0 · R24 §5.6 空分组反向对照（三态语义）

- **做法**：免打扰**允许名单**设成一个**没有任何成员**的分组（现成的 G2 就是 0 人）→ 触发任意 @消息 → **应该不静音**
- **为什么 P0**：`[]`=不限制 ≠ `["g:3"]` 但分组空=**谁都不命中**。两者混同会**反向失效** —— 若这条静音了，说明退化成「允许所有人」，实际效果是**静音全部通知**
- **出处**：`docs/_r24_picker_tabs.md` §5.6、§7.6

### 2.2 R24 §5.4 免打扰 `g:` / `t:` 前缀

名单里勾一个分组 → 触发一条 @我的群消息 → 应静音。
⚠️ 若「改名单后 30 秒内行为没变」，先确认 `invalidateScope` 是否触发（已加后台预热），**不是**前缀展开失效。

### 2.3 R24 §5.5 朋友圈导出 `g:` / `t:` 前缀

配含 `g:` 的导出名单 → 观察导出条数。「配了但一条都不导」= `listImpossible` 生效（正确行为），需先确认成员真实存在。

### 2.4 R25 自动导出的「真落盘」

已验链路通（`poke reason=bg-sync` → `export done rows=7 written=0 skipped=7`，幂等生效），
但 `written=0` 说明当时名单内没有新动态。**要看到真的生成新文件，需某位好友新发一条朋友圈后观察。**
出处：`docs/_r25_moments_bg.md`
