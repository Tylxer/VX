## 会话列表（K7 / ConvFilter）
- 结构：`ConversationListView` → `HeaderViewListAdapter`(headers=14,footers=1) → `mAdapter=com.tencent.mm.ui.conversation.p3`（2900+ 项）→ `getItem()=com.tencent.mm.storage.r4`(field_username)。
- **「停在顶部」≠ child0.top==0**：顶部栏是第一个 header，正常停靠 **-2713**（运行时抓，别硬编码）。`setSelectionFromTop(0,0)` 会制造 ~2051px 虚假下拉 → 弹小程序面板。
- **`ListView.correctTooHigh()` 会整块下移内容**（`fillSpecific` 里也调）→ 只能 hook 吞掉（`before` 里 `param.result=null`）。⚠️ 已废弃方案：补尾部填充行（会把 lastBottom 钉死 → cannotScrollUp 恒假 → 上拉滚到底空白）。
- 换 adapter 后必须按新 `viewTypeCount` 重建 `RecycleBin`，否则回收池串类型 → 会话行整片空白。
- **AOSP 滚动边界对巨型 header 不成立**：`cannotScrollDown` 恒假 → 下拉无限制。见 `ScrollDock`：hook `trackMotionScroll`，after 里把 child0.top 钳回停靠位（`offsetChildrenTopAndBottom` 是 @hide，**必须反射**，失败一次永久停用）。
  ⚠️ **两个守卫分开**：吞 correctTooHigh 只看结构（`firstVisiblePosition==0 && child0.top<0`）；下拉钳制只看筛选态（`currentGroupId()>0`）。不筛选时 firstVisiblePosition **也是 0**。
- **`headerAnchor` 只认藏得最到位的那次（取 min）**（可动区间 [dock,0]，用户下拉停在 -1500 也是 0）。`restoreAnchor` 拿不到锚点要 **return 不要退回 0**。
- 行点击走**每行自己的 OnClickListener**，不走 `performItemClick`（`onItemClick` hook 零命中）。
- `ConversationListView` 覆写了 set/get `OnItemClickListener` → `is ClickRemap` 判幂等失效 → 必须剥到最里层（`unwrapLongClick`）+ ThreadLocal 重入守卫，否则无限递归 ANR。
- `AbsListView.LayoutParams.viewType` 是包内可见字段，读要反射。
- 实测项数：不筛选 2957（内容溢出），筛选态 2。

## 会话长按菜单（A15 / ConvMenuInject）
- **微信长按菜单是自绘 PopupWindow，跟 AOSP ContextMenu 是两条平行链路**：
  `PopupWindow$PopupDecorView(601x884)` → `va4.m4`(容器) → `va4.j3`(525x808, ListView 子类) → 4 个 TextView（行高 202）。
  不走 `MenuBuilder.add`（零命中）、不走 `View.createContextMenu`（那条链全空）。
- **K7 的 `LongClickRemap` 会让这 4 项菜单消失** → 开关 `chat.conv_longclick_remap` **默认 false（弃用该包装）**。分组行长按走 `GroupRowMenu`，不受影响。
- 注入方案：hook `View.performLongClick`(2 重载) 的 **before** 记 lastWxid（`getPositionForView`+`ConvFilter.wxidAt`，早于 show 约 60ms）；hook `PopupWindow.showAsDropDown/showAtLocation`(5 重载) 的 **after**，4 秒窗口内动手。
  ⚠️ show 瞬间容器是空的 → 主线程轮询重试（0/40/80…ms，最多 8 次）。
  ⚠️ 容器是 AdapterView，`addView` 抛 UnsupportedOperationException → 走 `ListView.addFooterView(v,null,false)`（isSelectable=false 必须，否则同时触发微信 OnItemClick，footer 位置 getItem 为 null 可能崩）。
  ⚠️ 加进去的 View 必须是 `AbsListView.LayoutParams`（`setupChild` 无条件强转，普通 LP → CCE 崩微信）。
  ⚠️ 窗口固定高度（601x884，列表 808=4×202 刚好填满）→ 必须让 box/父容器/popup 一起长高 `行高×项数`，再 `popup.update(w,h+need)`（只接受 >0）。
- **adb 长按触发不了微信菜单**（被识别成点击），必须真手长按。做基线对照时触发方式要和实验组一致。
- 探针 `probe/MenuHuntProbe.kt`：`op=menuhunt sub=on|off|flush|tree|win|snap|clear [--ei sec N]`，70 个候选 hook + 不依赖 hook 的 View 树 diff。长按自动开 8 秒窗口；测完务必 `sub=off`（hook 了 addView/setVisibility 会拖慢微信）。
  ⚠️ 调用栈过滤没剔 LSPosed 桥接帧 → 要看真实调用点读每条 HIT 行 `at` 后**第 4 帧起**。
- 自弹 AlertDialog 方案（v0.2.5 `feature/ConvMenu.kt`）**已删除**。

## 分组行长按菜单 / 标记已读（v0.2.2）
- 长按菜单自己弹 AlertDialog（`GroupRowMenu`），**别注入微信的长按菜单**（那个 PopupWindow 无可挂 hook）。
- **长按回调必须 return true**（false 会冒泡 → 微信按会话处理弹「删除该聊天」/ 变点击）。
- **长按 listener 包装必须有调用期重入守卫**：微信 `conversation.z2` 在 `onItemLongClick` 内会回头调 `list.getOnItemLongClickListener()` 拿到我们的 wrapper → 无限回环栈溢出。`unwrapLongClick` 救不了。重入时返回 **true**。
- **Dialog 的 Context**：`HostContext.activity()` 靠 hook `Activity.onResume`，但 **LauncherUI 覆写了 onResume，hook 基类不触发** → 恒 null → BadTokenException。已改 `Application.registerActivityLifecycleCallbacks`。需 Dialog 处**优先用 View.getContext**。
- `GroupedAdapter.rebuild()` 的指纹缓存**必须含分组状态**（`db.listGroups().hashCode()`），否则置顶/重命名/删分组后列表不刷新。
- A7 标记已读只改内存（`field_unReadCount`=0），重启微信恢复；真落库需 DexKit 定位写库接口，别硬猜混淆名。
- A13：会话对象 `field_flag` 恒为 `conversationTime | (1<<62)`，**没有置顶位** → adapter 判不出原生置顶区块，pinned 分组行排最前。

## 返回键 / 退出行为（v0.2.1）
- **LauncherUI 的返回不在 `onBackPressed` 里**：走 `dispatchKeyEvent` → `HomeUI.r()` → `LauncherUI.moveTaskToBack()`，拦 onBackPressed **永远来不及**。
- 要拦返回：hook `LauncherUI`（沿继承链）的 `dispatchKeyEvent`，`KEYCODE_BACK + ACTION_DOWN + repeatCount==0` → `param.result=true`。
- 判定「在会话列表而非聊天页」：我们包装的 ListView 是否 `isShown && windowVisibility==VISIBLE`；取不到**保守放行**。
- 筛选态没有「返回全部」行，退出筛选靠系统返回键。
- 定位「谁把 App 退出去了」：hook `Activity.moveTaskToBack`/`finish` 打 16 层 stackTrace。

## 通知静音（K9 / NotifyMute）
- 通知**只在主进程** `com.tencent.mm` 发出（`:push` 一条没有）→ 装 bootstrap 即可，DB 直接可用。
- **「来自哪个群」只能从 `NotificationItem` 拿**（extras 无 chatroom id，contentIntent 反射取不到）。字段 `d`=id(int)、`h`=talker。`NotificationItem.a` 是**实例方法**（nargs=1）→ `hookAllMethods(cls,"a")` 拿得到 thisObject。取法两级降级：先正则解析 `toString()`（`id: ...,msgId: ...,userName: ...,unreadCount: ...`，功能性格式比混淆字段名稳），失败退字段名。
- `notify(String tag,int id,Notification)`，tag 恒 null，**id 与 `NotificationItem.d` 一一对应且稳定**。
- **响铃和震动不在 Notification 对象上**（sound/vibrate 全 null，defaults=0），是系统按 channel `message_channel_new_id` 播的（`[300,200,300,200]`）→ 改 Notification 字段**没用**，正解是**反射换 `mChannelId` 为自建静音通道**（IMPORTANCE_HIGH + setSound(null) + enableVibration(false)），通知栏/角标/heads-up 全部原样，连提示音也一起掐掉。
- **微信前台不响铃不震动** → 验证必须 `input keyevent 3` 退后台，否则探针抓不到。
- 来电判据（取自真机 VOIP 通知，**放行逻辑未真机验证**）：`category=call` / channel 以 `voip_` 开头 / `fullScreenIntent != null`，任一即可。
- ⚠️ PrefKind 要和读法对齐：TEXT 项（`chat.at_aliases`）**不能**用 `Kv.getList()`（按 JSON 数组解析，裸文本返回空列表）。昵称匹配防短名误伤：`@V` 会命中 `@Verity` → 要求 @alias 后不是字母/数字/下划线/短横线。
- 验证静音类功能**必须做反向对照**（关开关再发一条，确认恢复响+震）。

## 朋友圈（SnsGuard 防删除 / SnsTag 标签）—— 已真机全链路通过（2026-10-16）
1. **独立库** `MicroMsg/<md5>/SnsMicroMsg.db`（不是 EnMicroMsg.db）。`SnsInfo` 18 列 / `SnsComment` 16 列。模块库 `wxgroup.db` 表 `sns_archive`。
2. **删动态 = 物理 DELETE，两步**：① `update SnsInfo` 清 `localFlag` 可见位（bit4=16，落成 2）② `DELETE`。只拦②行还在但查不出 → **必须拦完写回 `localFlag |= 16`**（2→18）。时间线查询是白名单枚举（`localFlag in (16,2064,18,2066,24,…)`），每个值都置了 bit4。
3. **别人的动态在本地也会被 DELETE**（归档 userName 全是不同好友）→ **不区分作者一律拦**。
4. **标签落点走 adapter 绑定回调**：新版时间线 `ImproveSnsTimelineUI`；`com.tencent.mm.view.recyclerview.WxRecyclerAdapter` **类名未混淆**，`onBindViewHolder(holder,pos)` + `adapter.getData()`（元素 toString 含 `ImproveInfo(name=…, snsID='无符号十进制')`）。
   ❌ 老版 `View.setTag → TimeLineObject.Id` 链在新版**不存在**（唯一 sns 前缀 tag 只有表名 `sns_table_xxx`）；
   ❌ `getChildAdapterPosition` 在微信重打包的 androidx 里**不存在**，ViewHolder 位置字段恒 -1。
5. **标签实现铁律**：
   - onBind 开头必须 `adapter.javaClass.name.startsWith("com.tencent.mm.plugin.sns.")` 早退（钩子挂基类，全微信列表都进来）。
   - 子类覆写会让基类钩子变死钩 → 补挂 `WxRecyclerView.setAdapter` 抓具体类；2 参/3 参重载都挂。
   - `position` 与 `getData()` 下标**错位**（封面头，offset=-1/-2）→ 用 item 作者文字与 `ImproveInfo.name` 对账，**±2 窗口必须唯一命中**才采用（同作者相邻动态会互相通过校验）。
   - ⚠️ `holder → itemView` **必须排除 RecyclerView**（holder 持有 rv 引用，面积最大会选中它 → 所有 holder 同一个 View、标签加到列表容器上；**往 RecyclerView addView 会把微信搞崩**）。
   - item 根布局实测 **LinearLayout 子类** → 必须 `addView(tv, 0, lp)` 插最前，否则标签跑到底部、看着像贴在**下一条**上。
   - 严格校验：拿不到名字 / 读不到文字 / 名字 <2 字 → 不采信（打错标签比不打标签糟）。
   - `sns_archive` 只查 `sns_id` 一列且**不能加 LIMIT**（无 ORDER BY 时 LIMIT 取任意 N 行 → 静默漏标）。
   - 开关闸门必须在 onBind 最前面（否则关开关后滚动照样打标，2 秒后被 sweep 摘掉 → 反复闪）。
6. **snsId 符号**：库里有符号 Long（`-3447438253133393222`），`ImproveInfo.snsID` 是**无符号十进制 String**（`15033691623173788268`）→ `Long.parseUnsignedLong` / `toUnsignedString` 互转。写入端与读取端位模式必须一致（已有单测锁住）。
7. **探针**：`op=snstag sub=stat|dump|mark|fake|unmark`；`op=snsg sub=flags|fixall|simdel|show|del|cmts|one|stat|dump`。
   ⚠️ **`snsg dump` 里的 `flag` 是归档快照**（恒为 2），**不代表当前值**；查当前用 `snsg flags`。
   ⚠️ `snsg dump` / `one` 的输出**没有统一前缀**，grep 别按前缀过滤。
8. **`SnsComment` 16 列，无 content 列** —— 评论正文在 `curActionBuf` BLOB 里。列：`snsID/parentID/isRead/createTime/talker/type/isSend/curActionBuf/refActionBuf/commentSvrID/clientId/commentflag/isSilence/springWishFlag/isReminding/msgRelevanceType`。`attrBuf` 实测 235B~1069B。
9. 评论 `[已删除]` 标签**未实现**。开工前先实证：删评论时微信有没有重写 `SnsInfo.attrBuf`（没重写 → 只需拦 `delete SnsComment`；重写 → 要 protobuf 差量合并，工作量大一个量级）。

### 6.4 朋友圈 定时刷新 / 自动加载 / 自动导出（2026-10-17，lane/moments，**未上真机**）

**已落地（全部站在上面 1~9 条已验证结论上，没有新增猜测的类名/字段名）：**
- 调度：`MomentsLogic.nextRefreshAt`（单测锁住）；环境 = `BatteryManager.isCharging` / `ConnectivityManager` 的 `TRANSPORT_WIFI`，跑在微信进程里直接拿宿主的 Context（`HostContext.app()`，bootstrap 时已 `setApp`）。
- 自动加载：复用第 4 条的 `WxRecyclerAdapter.onBindViewHolder` + `getData()` 映射链（只取 pos/size，不做名字对账），贴底（最后 3 条）时对 item 父链上的 RecyclerView 调**公有 API** `fling(0, 8000)` 替用户甩到底，让微信自己的「滑到底加载更多」继续工作。节流 1.5s、每轮上限 30 次。
- 时间线 Activity：简单类名 `ImproveSnsTimelineUI` 已验证；**全限定名不猜** —— `registerActivityLifecycleCallbacks`（框架主动回调，不受子类覆写 onResume 影响，HostContext 同款）在用户真正进过一次朋友圈后按简单类名捕获，之后才允许自动拉起。
- 自动导出：数据源 `sns_archive`，`GroupDb.listSnsArchiveBefore` 键集分页（`(create_time, sns_id)` 复合游标，一次一页读 BLOB，内存有界）；文本渲染 `MomentsLogic.renderText`；目录 `MomentsLogic.exportDir`；去重 = 扫导出树里 `<snsId>.txt`（`parseExportedId`）；名单 `listHit`；空间下限 `MIN_FREE_BYTES`；tmp + rename 原子落盘；后台守护线程 + 单航班。
- 探针：`op=moments sub=stat|env|act|refresh|load|export|img|scan|path`（`EntryReceiver`）；`kvset` 改开关后热刷。

**⛔ 取证缺口（按优先级，都需要主代理安排真机）：**
1. **显式 Intent 重进时间线是否真的触发服务端拉取**（还是只走本地 onResume）。探针：`op=moments sub=refresh` 后看 ①`MOMENT autoload grow a -> b`（getData().size 变大）②SnsMicroMsg.db 有无新写入。若无效，退路是在时间线已前台时改走「真实下滑手势注入」，但那条路有误触风险，要单独评估。
2. **朋友圈缓存图片的磁盘命名规则**（url md5？snsId+序号？）。探针：`python tools/_moments.py --img` 打出 `mediaKeys` 全部候选串，与真机 `<sdcard>/Android/data/com.tencent.mm/MicroMsg/<md5>/sns/` 下的真实文件名对账。对上之前 `COPY_IMAGES=false`，只导文本。
3. **底部 fling 是否稳定触发微信「加载更多」**（不同 ROM 的 Fling 动画时长/惯性可能让 onScrollStateChanged 不落 IDLE）。自观测信号就是第 4 条的 grow 日志；不稳就退 `smoothScrollToPosition(size-1)` 或两者都试。
4. 从归档反插 `sns_archive → SnsInfo`（_restore.py 的 `snsg sub=restore`）：INSERT 只提供 13 个已知列，其余 5 列靠默认值 —— 若有 NOT NULL 无默认值列会失败，需真机看报错再补。
