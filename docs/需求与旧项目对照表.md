## 四、冲突点（需要你拍板）

### 1. VersionGate —— 旧项目有，但按 v5.8 的决定要删

旧项目 `core/VersionGate.kt` 做的是：**校验微信版本 + APK 签名 SHA256**，不匹配就 `DISABLED` 直接停用整个模块。

这跟我们 v5.8「删除 E6 版本降级保护」的决定冲突。两种理解：

- **按决定删掉**：只保留 try/catch 兜底。风险：微信自动升级后 hook 找不到类，最坏是崩溃
- **保留但静默**：不做提示、不做版本检测，只保留**签名校验**（防止模块被装到非目标包上乱跑）。成本几乎为零

### 2. 备份的两个策略要分开

旧 `BackupIO.restore(db, snap, replace)` 只有一个全局 `replace` 开关。我们要的是两条独立规则：

- 分组：取并集（旧项目的 `replace=false` 就是这个语义 ✓）
- 配置：只覆盖备份文件里存在的项

得把这两个拆成独立参数，不能共用一个 `replace`。

## 五、建议的落地顺序

1. 复制旧项目到本工作区，改包名为 `com.lx.wxgroup`，先确保能编译
2. 改数据层：`wxid` UNIQUE（成员独占）
3. 改造 `ConvFilter`：从「按选中分组过滤」→「始终隐藏已归组 + 按时间插入分组行」（**这是全项目最难的一步**）
4. 新建弹窗主界面，把已有的 GroupManager / BackupPage 挂进去
5. 逐个补四个新功能域的弹窗页（UI 可先做，hook 后补）
6. 最后接四个新功能域的 hook（需要实机定位锚点）
