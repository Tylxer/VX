# wxgroup 模块开发流程与原则

目标：**快**（少等真机）和**省**（少烧 token）。本文是流程层，
操作细节在 `docs/开发回路速查.md`，技术结论在 `docs/取证结论.md`。

---

## 一、五阶段流程（每个功能都这么走）

```
阶段0 定位/取证  →  阶段1 纯逻辑+单测  →  阶段2 实现  →  阶段3 真机验证  →  阶段4 固化
   （真机探针）      （JVM，0 秒）        （写代码）     （攒齐一轮）      （文档+记忆+提交）
```

### 阶段0 定位 / 取证
- **不要猜链路**。先用模块内探针（`op=... sub=...` 广播）或 `adb` 取证，拿到真实类名/字段名。
- 已有结论**先查 `docs/取证结论.md`**，别重复取证（这是最贵的浪费：一轮取证 ≈ 一轮真机）。
- 取证要**一次重启抓完多个问题**（每次重启微信 ≈ 30 秒且不确定）。

### 阶段1 纯逻辑 + 单测
- 把判据（解析、对账、SQL 改写、布局计算）放进**零 Android 依赖**的类，配 JVM 单测。
  现有范式：`feature/SnsTagLogic.kt`、`ConvLayout`、`SnsSql`。
- **理由**：这类逻辑错了就要重上一轮真机（≈2 分钟 + 大量排查 token）。单测 16 秒。
- 判据的测试数据**用真机抓到的真实样本**，不要编。

### 阶段2 实现
- 读源码：Grep 定位行号 → `Read(offset, limit)`。**禁止整读 >300 行的文件**
  （本模块有 6 个文件 500~1600 行）。
- 改动**攒齐再编译**（编译只要 10~14 秒，不是瓶颈；瓶颈是上机）。

### 阶段3 真机验证
- 一条命令：`python tools/dev.py loop <场景> --grep '关键字'`。
- 读数顺序见速查手册（先确认钩子活着，再看解析率，最后看落点）。
- **必须做反向对照**（关开关再复现一次），否则分不清「功能生效」和「环境本来就这样」。

### 阶段4 固化
- 结论写进 `docs/取证结论.md`，坑写进 `.workbuddy/memory/MEMORY.md`（**MEMORY.md 要小**，
  详见下面第三条原则）。
- 提交时 `git diff --stat` 看增删行数是否异常。

## 二、省 token 的八条硬原则

| # | 原则 | 不做会怎样 |
|---|---|---|
| 1 | **日志必须用 `dev.py q` 过滤** | 落盘日志 390KB+，一次误读上万 token |
| 2 | **截图是最后手段，先 `dev.py ui <文本>`** | 一张 1440×3200 截图 ≈ 上千 token；文本断言还能拿到 y 坐标做量化判断 |
| 3 | **MEMORY.md 保持 <4KB**，细节放 `docs/` 按需读 | 记忆每会话**全量注入**，超长会被截断 —— 17.5KB 时后一半（正是当前开发重点）看不到 |
| 4 | **复核子代理给 diff，不给全文件** | 一个 866 行文件喂给复核 agent，等于付双倍 token |
| 5 | **改动攒齐再上机** | 改一处上一轮是最贵的浪费（一轮 ≈ 2 分钟） |
| 6 | **不重复取证**：先查 `docs/取证结论.md` | 一轮取证 ≈ 一轮真机 |
| 7 | **纯判据单测化** | 靠真机试判据，错了要重来一整轮 |
| 8 | **会话开始先读 MEMORY.md + 速查手册** | 不读就会重新踩坑（LogX 上限、apk_path、广播不投递…每个坑值十几分钟） |

## 三、多 agent 并行协议（**按「只读、不抢设备」执行**）

**总原则：真机是硬串行瓶颈，禁止并行改源码。默认所有并行任务都是只读的。**

原因（都是实测约束，不是保守）：
1. **只有一台设备、一个微信进程、一份落盘日志**。两个 agent 同时 `install` 会互相覆盖 APK，
   同时拉日志会互相污染，谁的结果都不可信。
2. **模块是单进程内联 hook**。会话列表 / 朋友圈 / 防撤回都跑在同一个 `com.tencent.mm` 进程里，
   一个功能崩了会带崩全部，并行改动无法归因。
3. **LSPosed 模块重载不确定**（`force-stop` 第一次常是旧代码），并行时更难判断「跑的到底是谁的代码」。

### 判定规则（派活前先过这一条）
> **会写 `app/src/main` 下的文件，或要碰设备（install / 跑场景 / 拉日志）→ 串行。其余 → 可并行。**

### ✅ 可并行白名单（只读，不抢设备）
| 任务 | 派发要求（照抄，别自由发挥） |
|---|---|
| **独立复核** | 只给 `git diff`，**不给全文件**。提示词写清：只读复核、**不要修改任何文件**、按「必须修/建议改/可接受」三档输出、每条给 `文件:行号 + 具体修法` |
| **只读取证** | 读源码 / 分析已 pull 下来的日志 / 分析 DB —— 不占用设备 |
| **文档与单测编写** | 只碰 `docs/` 与 `app/src/test`，不碰 `app/src/main` |
| **纯逻辑类设计** | 新建 `*Logic.kt`（零 Android 依赖）时可与主实现并行，最后一次性接线 |

### ❌ 必须串行
| 任务 | 原因 |
|---|---|
| 改 `app/src/main` 下的源码 | 编译产物互相覆盖 |
| 一切 `adb install` / 跑场景 / 拉日志 | 设备与日志是单一资源 |

### 若真的要并行改代码：按「功能文件」切，不按「阶段」切
- 文件**不重叠** + 真机验证**排队**；谁要跑真机先说一声，期间对方只做只读任务。
- ⚠️ 本模块 .kt 之间耦合较紧（共用 `Kv`/`GroupDb`/`LogX`），切分前先确认**没有共享文件改动**。
- 例：A 做评论标签（`SnsCommentTag*`）、B 做 K3 选择器接入（`PickerPage`/`BatchPicker`）。

## 四、工具覆盖度 & 自动化场景脚本缺口（⏳ 待用户确认后开工）

| 能力 | 覆盖情况 |
|---|---|
| 真机回路编排、日志过滤、UI 断言 | ✅ 通用（`tools/dev.py`） |
| 纯逻辑单测 | ✅ 已覆盖 SnsTagLogic / ConvLayout / SnsSql / CvCodec / BackupCodec |
| 探针（模块内广播） | ✅ 14 个 op，但**速查手册只登记了 sns 系列**，其余待补 |
| LSPosed 路径修复 | ✅ `tools/_lspfix.py` + 自动加载检测（5 秒判据） |

公共库 **`tools/_lib.py`**：adb / 广播 / kvset / UI 断言 / `wait_manual` / 日志过滤。
新脚本一律 `from _lib import *`，别再复制粘贴那套 `sh()/bc()/top()`。

> ⏳ 这些脚本面向**未实现**的功能：现在跑会显示「功能未接通/探针 unknown」，属预期。
> 脚本的价值是把「导航 + 开关 + 断言」固化下来，功能上线那一刻直接可用。
