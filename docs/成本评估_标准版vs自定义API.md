# 成本评估：标准版内置模型 vs 自定义 API（wxgroup 开发）

> 评估日期：2026-11-08
> 数据来源：用户账单陈述 + `docs/派发审计台账.md`（R7–R43 路由与 lane 记录）
> 状态：结论已按用户两处修正重写，旧论点已剔除。

## 0. 一句话结论

**不能断言"内置更实惠"。** 账面内置 per-lane 成本低一半，但这是**阶段成熟度效应**（后期密集交付 vs 早期试错），不是计费方式优势。编排层在两段都免费（每日 100 积分），裸 DS token 单价本就低于内置 credits 折算价，所以**单论每 token 价格，自定义 API 大概率更低**。真正的取舍在"省心 vs 可控"，不在钱。

## 1. 已剔除的三个旧论点（作废）

1. ~~重叠付费/重复买~~ —— 200 元（前半月自定义 API）与 70 元（升级标准版后内置）是**先后两段**，非同时重复付费。
2. ~~路由混乱导致持续浪费~~ —— R33「写 Pro 实发 Flash」、R20b「PRO 计费对账」属**已解决的历史问题**，不计入当前/后续判断。
3. ~~内置 70 元"打包了编排"所以更值~~ —— 用户确认 agent 编排（子代理/工具/自动验证）由**每日赠送 100 积分**覆盖、够用。编排在两段均免费，不是内置独享价值。

## 2. 修正后的成本结构

| 成本项 | A 段：自定义 API | B 段：标准版内置 |
|---|---|---|
| 花费 | 200 元（DS 官方 + 腾讯云） | 70 元（WorkBuddy 积分） |
| 本质 | 裸 token 费 | 内置模型 token 费（credits） |
| 编排层 | 免费（每日 100 积分） | 免费（每日 100 积分） |
| 时段 | 约 13 天（10-19 ~ 10-31） | 约 7 天（11-01 起，密集 11-06~07） |
| 实现 lane（台账下限） | ≈22 | ≥15 |

⇒ 两边比的，是**纯 token 成本**；编排不再是区分项。

## 3. 账面 per-lane 对比

| 指标 | A（自定义） | B（内置） |
|---|---|---|
| 单位成本 | 200 ÷ 22 ≈ **9.1 元/lane** | 70 ÷ 15 ≈ **4.7 元/lane** |
| 日均成本 | ≈15.4 元/天 | ≈10 元/天 |

内置显示约一半单价，但**原因必须重新解释**（见 §4）。

## 4. 混杂因素（诚实标注）

1. **阶段成熟度是最大混淆变量**
   - A 段：早期探索，脚手架 + 分包下限未达标的 0-lane 轮次多，纯耗 token 不出活。
   - B 段：后期成熟，代码定型，R42 密集爆发交付"朋友圈防删除全链路"。
   - B 的高效主要来自"更熟了"，非"内置更便宜"。

2. **裸 DS token 市场价 < 内置 credits 折算价**
   - DeepSeek 官方约 ¥1–4 / 百万 token。
   - 内置 `deepseek-v4-pro` credits 系数 x0.51，仍含平台溢价。
   - 反推：B 段 4.7 元/lane 低于 A 段 9.1 元/lane，**大概率是阶段效率差，不是内置 token 更便宜**。阶段归一后，自定义 API 每 token 成本可能反而更低。

## 5. 修正结论

- **不成立**："内置更实惠"建立在打包价 / token 更便宜上 → 两者均不成立（编排免费、裸 DS 单价更低）。
- **账面事实**：内置 per-lane 低一半，但属后期成熟阶段 + 密集交付的阶段效应。
- **真实取舍不在钱**：两边编排免费、token 皆主成本。选哪个看——
  - 内置：**省心**（免管 key/配额、模型随平台更新）；
  - 自定义：**可控**（直连、特定模型、批量脚本化调用）。
- 若硬比 token 单价：自定义 API 大概率更低。
