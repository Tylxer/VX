# 拍一拍「关闭拍一拍」取证方案

> 需求 6.1「关闭拍一拍」= **禁用双击头像触发拍一拍**（阻止自己发出，方向已定死）。
> 本文只回答一件事：**下一轮真机要跑什么、看什么日志、怎么判定成功**。
> 代码侧已全部就位、**均未上真机**：`PatLogic`（纯判据 + 单测）、`PatBlock`（hook 主体 + 取证探针）、`EntryReceiver` 接线（`op=quiet sub=pat sub2=…`）。

---

## 一、现状一句话

- 拍一拍触发锚点（类 / 方法 / 参数个数）**未取证** → `PatBlock` 顶部三个常量留空 / -1。
- 已实现的取证探针 `dbltap`：hook **Android framework 的 `GestureDetector#onTouchEvent`**，
  反射读 `mDoubleTapListener` 字段的**实际实现类名** + dump 调用栈。零猜测锚点。
- 为什么 hook `onTouchEvent` 而不是 `OnDoubleTapListener#onDoubleTap`：后者是**接口抽象方法**，
  Xposed `hookMethod` 对无实现体的接口方法必然抛 `IllegalArgumentException`（真机已踩过，
  `sub2=dbltap` 返回 `error=IllegalArgumentException`）。

---

## 二、目标

拿到「双击聊天页对方头像 → 触发拍一拍」这条链路上**微信自己的类名 + 方法名**，
回填 `PatBlock` 的三个常量即可让「阻止发出」生效：

```kotlin
PAT_TRIGGER_CLASS_8048   // 触发拍一拍的业务类
PAT_TRIGGER_METHOD_8048  // 触发方法名
PAT_TRIGGER_ARG_COUNT_8048 // 方法参数个数（-1 = 不校验参数个数）
```

---

## 三、取证步骤（按序执行）

### 0. 前置

- 编译 + 装真机（本项目的标准回路，`dev.sh sync` / `adb install -r`）。
- ⚠️ 装完先确认模块已注入：日志里有 `<功能> installed`（拍一拍这块 `install` 会打
  `QUIET PAT skipped: …trigger anchor pending evidence`，说明锚点还没填、正常）。
- 测前 `op=logclear` 清日志（LogX 环形 5000 行）。

### 1. 打开双击取证

```
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm \
  --es op quiet --es sub pat --es sub2 dbltap
```

预期回显（`dev.py q 'QUIET'` 或 `dev.py q 'PATDBG'`）：
`QUIET dbltap hook installed GestureDetector#onTouchEvent field=ok max=50, go double-tap an avatar now`

> ⚠️ **`field=ok` 里只有状态**（对应 `PatBlock.kt:197` 的 `field=$fieldState`）；**带字段全名的是
> 另一行** `PATDBG dbltap probe installed: GestureDetector#onTouchEvent field=mDoubleTapListener=ok`
> （`PatBlock.kt:196`）。两行别混。
>
> ⚠️ `field=MISSING(only stack available)`（`QUIET` 那行）也**可以继续**：
> 拿不到字段就只剩栈可看，栈里照样有微信类名。

### 2. 去聊天页双击一次对方头像

双击动作要**落在对方头像上**（不是消息气泡、不是自己头像）。

### 3. 拉日志看

```
python tools/dev.py q 'PATDBG'
```

## 四、判定：三种结果，三种应对

### ✅ 结果 A：拿到微信业务类（成功）

日志出现类似：

```
PATDBG dbltap-listener=com.tencent.mm.ui.chatting.xxxx.PatAvatarHelper   ← 关键一行
PATDBG   #0 com.tencent.mm.plugin.xxx.Yyy#onDoubleTap
PATDBG   #1 com.tencent.mm.ui.chatting.ChattingUI#...
...
```

判定成功标准（**同时满足**）：
1. `dbltap-listener=` 后面是 `com.tencent.mm.*` 的类（不是 `android.view.*` 默认实现）；
2. 栈里有可读的微信方法名，且能看出「这是处理双击/头像/拍一拍的那一次调用」。

**回填动作**：把最靠业务语义的那一帧（通常是 listener 类本身、或栈里紧接着的
`onDoubleTap` / `onPat…` / `pai…` 方法）填进 `PatBlock` 三常量。
若栈里方法参数个数不确定，`PAT_TRIGGER_ARG_COUNT_8048` 先填 `-1`（不校验参数个数）。

### ⚠️ 结果 B：`dbltap-listener=` 是 `android.view.*` 或空

说明微信的聊天头像双击**没走 `GestureDetector`**（自己计时判定双击，或用了
自定义手势组件）。此时锚点不在这里。**不要硬填**，转方向（见 §六 备选）。

### ⚠️ 结果 C：栈里全是 `com.tencent.mm` 但**分不出哪个是拍一拍**

把 `PATDBG` 里所有 `#i` 帧**原样回传**（或拉完整 LogX），人工从
`onDoubleTap` / `pat` / `pai` / `avatar` / `head` 关键词里筛（判据
`PatLogic.classCandidates` / `methodCandidates` 就是干这个的）。

## 五、拿到锚点后的回填 + 验证（交叉验证，真机前必做）

1. 回填 `PatBlock` 三常量 → 跑 `PatLogic` 单测（判据无改动，只锁开关/文本/限流）。
2. **交叉验证**（本项目硬规则）：把 diff 交第二个视角复核，确认
   - 锚点是「触发拍一拍」而不是「普通头像点击」（误拦 = 头像点不开）；
   - `PAT_TRIGGER_ARG_COUNT_8048` 与真实方法签名一致（填错 = 反射匹配不到 → 静默不拦）。
3. 上机：`sub2=anchor` 看回显确认已回填；`sub2=status` 看 `installed=true hooks=N`。
4. 验证拦截：开「关闭拍一拍」开关 → 双击对方头像 → 对方**不再收到**「XX 拍了拍 XX」；
   关开关 → 双击 → 正常拍。两条都要验（防「关了也失灵」）。

## 六、备选取证点（结果 B 时用，按优先级）

| 优先级 | 方向 | 做法 | 代价 |
|---|---|---|---|
| 1 | 头像 View 的 `onTouchEvent` | 先定位聊天页头像 View 类（可从栈结果 B 的帧里找头像相关类），hook 它 `onTouchEvent` 数「两次 tap 时间差 < 双击阈值」 | 需要先有头像 View 类名，鸡生蛋 |
| 2 | 反向：拦「拍一拍系统消息」的**收发** | 不找触发点，hook 消息类型/发送入口，判据 `PatLogic.shouldBlockIncoming`（已实现 + 单测）。收到「拍了拍」系统消息即不展示/不发送 | 只能阻断「对方看到」，拦不到「自己已经发出」；语义与需求主方向有差 |
| 3 | 换手势组件 | 微信若用 `ScaleGestureDetector` / 自定义 `ViewConfiguration.getDoubleTapTimeout()`，则 hook 对应框架类 | 需再枚举一轮 |

> 需求主方向是「阻止自己发出」，结果 B 下优先走备选 1；备选 2 是**降级**（能挡住对方
> 看到，但自己侧已发出、只是不显示，会与「已发出」语义冲突，需要用户确认可接受）。

## 七、风险清单

1. **误拦普通头像点击**：锚点填错（把单击当双击）→ 头像点不开。回填前必须交叉验证。
2. **限流**：`GestureDetector#onTouchEvent` 是列表滑动热路径，探针已按「listener 类名
   去重 + 50 条上限」限流，**取证完必须 `sub2=dbltapoff` 卸载**，别让探针常驻拖慢列表。
3. **`hookMethod` 对接口方法必抛异常**：不要回退去 hook `OnDoubleTapListener`。
4. **模块注入**：`adb install -r` 后第一次冷启动常还是旧代码，判据是日志里有没有新
   `installed`；别用 `monkey` 拉微信。
5. **微信后台广播不投递**：发 `op=quiet …` 前先 `am start -n com.tencent.mm/.ui.LauncherUI`。
