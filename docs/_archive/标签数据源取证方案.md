## 一、结论一句话

**id → 标签名的映射，全项目没有任何实机锚点。**
能读的只有「这个联系人身上挂了哪些标签 id」，读不到「这些 id 叫什么」。
所以 K3 选择器的「数据源＝微信标签」目前**不具备实现条件**，先取证。

## 三、三个候选路径 + 各自的落地条件

### 路径 A：直接查微信库里的标签表（**首选，最省**）

- 可行性支撑：我们**已经在微信进程里握着它自己的 wcdb 句柄**
  （`AntiRevoke.wxDb()`，防撤回一直在用；`SnsGuard` 也在 `SnsMicroMsg.db` 上读写）。
  用它 `rawQuery` 就能读到数据 —— 库是加密的，但**用微信自己的句柄就不存在解密问题**。
- **落地条件（待取证）**：
  1. 标签表在不在 `AntiRevoke.wxDb()` 那个库里（`rcontact` 若在，标签表多半也在）；
  2. 表名叫什么（`sqlite_master` 枚举即答，**不许猜**）；
  3. 表里哪两列是 `id` 和 `name`（`pragma table_info` 即答）。
- 风险：若标签表在另一个库（像 `SnsMicroMsg.db` 那样），需要先抓到那个库的实例
  → 走探针 `sub=on` 收集，或复刻 `SnsGuard` 的安装方式。

### 路径 B：从联系人表的 `contactLabelIds` 列取「人 → id」，标签名仍需路径 A

- 可行性支撑：`rcontact` 是旧项目实测锚点；`field_contactLabelIds` 是字段名锚点。
- **落地条件（待取证）**：`rcontact` 里有没有这一列、值的**分隔符是什么**
  （`1,2,3`？`,1,2,`？）—— 分隔符未知，`LabelLogic.splitIds` 目前按候选集兼容。
- 注意：这条路只解决「人 → id」，**名字还是得靠路径 A**。

### 路径 C：hook 微信内部的标签查询方法 / 从「标签」UI 层抓

- 兜底路径。落地条件：定位到「通讯录 → 标签」列表页的 Fragment / Adapter 类名，
  或其数据加载方法（`MenuHuntProbe` / `UiProbe` 那套）。
- 代价最大（混淆名、换版本失效），**只有在 A/B 都证明走不通时才上**。

## 四、探针用法（已接线：`op=label`）

探针代码：`probe/LabelHuntProbe.kt`（**全程不含硬编表名**，表名一律 `sqlite_master` 枚举）。
日志前缀 `LABEL`，落盘 `wxgroup_dbg.txt`。

```sh
# 0（可选）开 60 秒窗口收集微信库实例；期间进通讯录 / 标签页滚一滚
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm --es op label --es sub on  --ei sec 60
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm --es op label --es sub dbs

# 1 每个库有哪些表，命中 label/tag/rcontact/contact 的列出来 + 行数
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm --es op label --es sub tables

# 2 看命中表的列名
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm --es op label --es sub info --es table <上一步的表名>

# 3 看样本行（这一步就能确定 id 列与 name 列）
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm --es op label --es sub rows --es table <表名> --ei n 5

# 4 任意只读 SQL（取证后期不用重新打包；只放行 select / explain / 只读 pragma，
#   判据见 LabelHuntProbe.isReadOnly：user_version / journal_mode / optimize 等
#   会改库文件的 pragma 一律被拒）
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm --es op label --es sub sql --es sql "select contactLabelIds from rcontact limit 5"

# 5 取完务必关掉（钩子挂在 rawQuery 热路径上；窗口到期也会自动摘）
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm --es op label --es sub off
```

⚠️ 上机前三件事照 `CLAUDE.md`：模块真的加载了吗 / `op=logclear` 清一次 / 微信在前台。

### 主代理拿到输出后怎么判断

| `sub=tables` 输出 | 结论 |
|---|---|
| 出现含 `label` 的表且 `rows>0` | **路径 A 成立**。接着 `info`+`rows` 拿 id/name 两列 → 可落地 |
| 只有 `rcontact`，无 label 表 | 标签表可能在别的库 → 先 `on` 开窗口再 `tables`；仍没有则转路径 C |
| 关键字一个没命中 | **别急着判定「没有」**：看 `all=` 后面列的全量表名（防关键字押空） |
| `sqlite_master 空 / 查不到` | 那个 db 实例已失效，换一个库或重启微信再来 |

`sub=rows` 里若出现 `contactLabelIds` 之类的列 → 顺手把**真实分隔符**记下来，
回填 `LabelLogic.SEPARATORS` 并给 `LabelLogicTest` 补一条用例。
