## 零、纪律与前置

### 0.1 铁律

- **不改 `PatLogic.kt` / `PatBlock.kt` 的判据与 hook**：本轮是取证，不是改功能。
- **只回填 `PatBlock.kt` 顶部三行常量**（见 §四），其余一行不动。
- **取证完必须卸载探针**（`sub2=dbltapoff`）：探针挂在
  `GestureDetector#onTouchEvent` 上是**列表滑动热路径**，常驻会拖慢微信（见 `PatBlock.kt:170`）。

### 0.2 前置回路

```bash

python tools/dev.py sync            # 或 adb install -r <apk>；别用 monkey 拉微信
```

**期望看到（锚点还没填，属正常）**：

```

```

> ⚠️ 若**看不到**这行 `QUIET PAT skipped: ...`，说明模块没进微信进程 / 没注入，**先别取证**，
> 回去查注入（`HookEntry.kt:233` → `PatBlock.install(lpparam)`）。

### 0.3 action 不要敲错

- action 是 **`com.lx.wxgroup.action.PROBE`**（模块**没有** `QUIET` 这个 action，敲错会静默无输出）。
- 功能选择 = `--es sub`（本功能是 `pat`）；子命令 = **`--es sub2`**（`dbltap` / `dbltapoff` / `anchor` / `status`）。
- 两个参数**不能混**：早先只用一个 `sub` 时 sub2 根本传不进来（`PatBlock.kt:38`）。

## 一、打开双击取证（`sub2=dbltap`）

```bash
adb shell am broadcast -a com.lx.wxgroup.action.PROBE -p com.tencent.mm \
  --es op quiet --es sub pat --es sub2 dbltap
```

### 期望回显（`python tools/dev.py q 'QUIET'`，字符串**逐字**来自 `PatBlock.kt:197`）：

```
QUIET dbltap hook installed GestureDetector#onTouchEvent field=ok max=50, go double-tap an avatar now
```

同时 `PATDBG` 有一条**更详细**的安装日志（`PatBlock.kt:196`），带字段全名：

```
PATDBG dbltap probe installed: GestureDetector#onTouchEvent field=mDoubleTapListener=ok
```

分支回显（按 `PatBlock.kt:181 / 197 / 195` 逐字）：

| 情况 | 回显 | 含义 | 下一步 |
|---|---|---|---|
| 首次挂载 | `QUIET dbltap hook installed GestureDetector#onTouchEvent field=ok max=50, go double-tap an avatar now` | 字段拿到 | 进 §二 |
| 字段拿不到 | `QUIET dbltap hook installed GestureDetector#onTouchEvent field=MISSING(only stack available) max=50, go double-tap an avatar now` | 只剩栈可看 | **仍可继续**：栈里照样有微信类名 |
| 重复挂 | `QUIET dbltap already hooked, re-armed (dumps reset)` | 幂等命中，计数已归零 | 直接进 §二（无需先 off） |
| 抛异常 | `QUIET dbltap error=<ExceptionSimpleName>` | 见 `PatBlock.kt:175` | 若为 `IllegalArgumentException`：**别回退去 hook `OnDoubleTapListener`**（接口无实现体，必炸，见 §五风险1） |

> ⚠️ 注意：`docs/拍一拍取证方案.md` §三.1 写的期望回显是 `field=mDoubleTapListener=ok`，
> 但**广播回显实际是 `field=ok`**（`fieldState` 只有 `ok` / `MISSING(...)`）；
> 带全名 `mDoubleTapListener` 的是 `PATDBG` 那条安装日志。以本节为准。

## 四、判定：三种结果，三种下一步

### ✅ 结果 A：拿到微信业务类（成功）

`dbltap-listener=` 后面是 `com.tencent.mm.*`（**不是** `android.view.*` 默认实现），
且栈里有可读的微信方法名，能看出「这是处理双击/头像/拍一拍的那一次调用」。

**回填动作**（只改 `PatBlock.kt:44-46` 三行，`PatBlock.kt` 顶部）：

```kotlin
// 原样（不改）：
private const val PAT_TRIGGER_CLASS_8048 = ""      // 待取证
private const val PAT_TRIGGER_METHOD_8048 = ""     // 待取证
private const val PAT_TRIGGER_ARG_COUNT_8048 = -1  // 待取证

// 例（值以真机日志为准，下同）：
private const val PAT_TRIGGER_CLASS_8048 = "com.tencent.mm.ui.chatting.xxxx.PatAvatarHelper"
private const val PAT_TRIGGER_METHOD_8048 = "onDoubleTap"
private const val PAT_TRIGGER_ARG_COUNT_8048 = -1   // 签名不确定就先 -1（不校验参数个数）
```

选帧原则：**取最靠业务语义的那一帧** —— 优先 listener 类本身，或栈里紧接着的
`onDoubleTap` / `onPat…` / `pai…` 方法。可用候选筛子手动收窄（`PatLogic.classCandidates` /
`PatLogic.methodCandidates`，关键词：类 `pat`/`pai`/`doubletap`；方法再加 `头像`/`avatar`/`head`）。

**回填后**：
1. 跑 `PatLogicTest` 单测（判据无改动，只锁开关/文本/限流——本轮不新增锚点常量）。
2. 走 §五 **交叉验证 checklist**。
3. 上机确认：`sub2=anchor` → `QUIET class=... method=... argc=... (evidence: op=quiet sub=pat sub2=dbltap)`
   （不再是 `class=待取证 method=待取证`）；`sub2=status` → `installed=true hooks=N`。
4. 反向验证：开开关 → 双击对方头像 → 对方**不再收到**「XX 拍了拍 XX」；关开关 → 双击 → 正常拍。

### ⚠️ 结果 B：`dbltap-listener=` 是 `android.view.*` 或空

说明微信聊天头像双击**没走 `GestureDetector`**（自己计时判定双击，或用自定义手势组件）。

**下一步（不要硬填锚点）**，按优先级转 `docs/拍一拍取证方案.md` §六备选：

1. **备选 1（首选）**：定位聊天页**头像 View 类**，hook 它的 `onTouchEvent`，数「两次 tap 时间差 <
   `ViewConfiguration.getDoubleTapTimeout()`」。做法：先从结果 B 的**栈帧**里扒头像相关类名
   （这一步栈仍是有的），再回到 `sub2=dbltap` 思路改挂那个 View 的方法。
2. **备选 2（降级）**：不找触发点，改拦「拍一拍系统消息」的**收发**，判据用
   `PatLogic.shouldBlockIncoming(enabledRaw, sysMsg, text)`（已实现 + 单测）。
   ⚠️ 语义有差：只能挡住**对方看到**，自己侧其实**已发出**，与需求主方向「阻止自己发出」冲突，
   **需用户确认可接受**。
3. **备选 3**：若微信用 `ScaleGestureDetector` / 自定义 `ViewConfiguration.getDoubleTapTimeout()`，
   再枚举一轮对应框架类。

---

### ⚠️ 结果 C：栈里全是 `com.tencent.mm` 但分不出哪个是拍一拍

1. **原样回传** `PATDBG` 里所有 `#i` 帧（或拉完整 LogX）。
2. 用关键词人工筛：`onDoubleTap` / `pat` / `pai` / `avatar` / `head` —— 即 `PatLogic.classCandidates` /
   `PatLogic.methodCandidates` 的筛子。
3. 拿不准时**再双击一次**（重新 `sub2=dbltap` 归零计数，或直接再双击），
   对比两轮共有的帧 —— 稳定出现且语义相关的那个就是候选。
4. 仍分不出：记为「本机未定论」，**保持三常量留空**，下一轮换结果 B 的备选路线。
