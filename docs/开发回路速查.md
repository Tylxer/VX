# 开发回路速查（先看这个，别重新探索）

本文件是**为了省 token 和省时间**存在的：所有已踩过的坑、已取证的类名/方法名、
现成工具都在这里。开工前扫一遍对应章节，能避开绝大多数「白跑一轮真机」。

各功能的**技术结论**在 `.workbuddy/memory/MEMORY.md`，本文件只讲**怎么干活**。

---

## 一、三条铁律（违反必定白烧 token）

1. **改动攒齐再上机**。编译只要 14 秒，但一轮完整真机回路 ≈ 2 分钟
   （install + LSPosed apk_path 修复 + 场景 sleep）。**改一处上一轮是最贵的浪费**。
2. **日志不许用 Read 工具直接读**。落盘日志 390KB+，一读就爆。
   必须 `python tools/dev.py q '正则' [n]`（自动去重 + 只打最后 N 行，默认 40）。
3. **截图是最后手段**。一张 1440×3200 截图 ≈ 上千 token。
   先 `python tools/dev.py ui 已删除` 做**文本断言**（uiautomator dump，输出 text+bounds
   按 y 排序），确认不了再截图。

## 二、一条命令跑完整回路

```bash
python tools/dev.py loop <场景名> --grep '关键字' [--n 40] [--skip-build]
```
流程 = 编译 → 安装 → （自动判断是否要）修 LSPosed apk_path → 跑 `tools/_<场景名>.py` → 拉日志 → 只打印匹配行。

## 三、上机前必做的三件事

| 检查 | 不做会怎样 |
|---|---|
| 测前清日志：`op=logclear` 广播（**不用重启微信**） | LogX 有 5000 行上限，写满是**环形覆盖**（不是停写），但旧日志会混进来干扰判断。清日志用广播，别 force-stop |
| **先跑场景看日志，确认没注入才修** | `dev.sh sync` 报 `[STALE] apk_path` **不等于没注入** —— 实测 STALE 时模块照样正常加载（日志有 `SNS_TAG installed`）。**判据是日志里有没有 `installed`**，不是 sync 的输出。无脑跑 `_lspfix.py` 每次白花 30 秒；只有「一条模块日志都没有」时才需要它 |
| 确认微信在前台 | 微信在后台时**广播不投递**，静默失败 |

判据：日志里出现 `SNS_TAG installed` / `K9 installed` 才说明新代码真的加载了。

## 四、探针速查（模块内广播，不用重新编译就能查状态）

```bash
adb shell am broadcast -a com.lx.wxgroup.action.PROBE \
  --es op <op> --es sub <sub> [--el id <long>] [--ei n <int>] -p com.tencent.mm
```

| op | sub | 用途 |
|---|---|---|
| `snstag` | `stat` / `dump` / `mark` / `fake` / `unmark` | 标签自诊断与强制打标 |
| `snsg` | `stat` / `dump` / `flags` / `fixall` / `simdel` / `show` / `del` / `cmts` / `one` | 朋友圈防删除 + SQL 取证 |
| `snsv` | `ids` / `recycler` / `dump` | View 树 / RecyclerView 取证 |
| — | `kvset` / `kvget` | 改/读配置（设备无 sqlite3，只能这样） |
| — | `logclear` | 清落盘日志 + 计数归零（**替代 force-stop 重启**，省 30 秒） |

⚠️ `snsg dump` 的 `flag` 是**归档快照**（恒为 2），不代表当前值；查当前用 `snsg flags`。
⚠️ `snsg dump` / `one` 的输出**没有统一前缀**，grep 别按前缀过滤。

## 五、自诊断读数顺序（SnsTag）

`snstag stat` 输出：`enabled / guard / tag / deleted / bound / added / binds / resolved / missed / lastMiss`

1. `binds > 0` —— 钩子活着（=0 说明 hook 没挂上或没限定到朋友圈）
2. `resolved ≈ binds` —— 解析通（真机 96.6%）
3. `missed` 接近 0，`lastMiss` 给出最后一条未解析的原因
4. `added > 0` 且 `hit=true` —— 标签打上且落点正确
