## C. 建议做（非阻塞，但显著降风险）

### C1. 群发风控预案（强烈建议）
全自动群发有封号风险。
**已定（决策 #8 / #9）**：
- 单批次目标数**不设上限**（用户已知风险并接受）
- **连续失败 5 条自动中止**整个任务并提示，而不是一直重试刷接口
- **不加**「试发 1 条」按钮，群发页只有「开始群发」

### C2. 朋友圈导出路径的权限实测（建议提前验证）
`/storage/emulated/0/Android/data/com.tencent.mm/files/` 是微信自己的应用专属目录，微信进程内可写无需权限——**但 Android 11+ 上用户用文件管理器看不到 `Android/data`**，导出后取文件会很痛苦。
建议开工前实测两件事：微信能否写入、用户能否取到。若取不到，改到 `Documents/WechatXposed/moments`（需要确认微信是否持有存储权限，可能需要 SAF 授权目录树）。

### C3. 最低可运行切片（v0.1）定义
**已定（决策 #5 / #14）：v0.1 不做任何界面**——不加 launcher、也不保留旧项目的广播入口。
范围收敛为：
1. 复制旧项目 → 改包名 `com.lx.wxgroup` → **编译通过**（唯一验收标准）
2. **K6 数据层落地**：5 张表 + 成员独占（username UNIQUE）+ `auto_dnd_done` + kv 表 + Keys 默认值

UI 与所有 hook 等 S3 定位后统一开工。这样 v0.1 不依赖任何未定位锚点，现在就能做完。

### C4. 里程碑与 git 策略
- 每个可运行里程碑一个 commit，docs 与 code 分开提交
- 建议 tag：`v0.1-skeleton` / `v0.2-conv` / `v0.3-settings` / …
- 每个里程碑保留一份已知问题清单

### C5. 探针覆盖补齐
旧 7 个探针覆盖 S1（会话列表）与 S8（通讯录）。S3/S4/S5/S6/S7/S9 需要新探针或 DexKit 定位脚本。定位一次，后续换微信版本能救命（旧项目 `probe/` 就是这么留下来的）。

### 关于第 4 问的技术答复：改到 Documents 会不会有权限问题

**结论：大概率能写，但我不建议在没实测前改默认路径。**

- 模块跑在微信进程内，uid 就是微信的 uid，**权限完全等于微信自己的权限**。
- 微信 8.0.48 至今仍在写 `/sdcard/tencent/MicroMsg/` 这种公共目录，这本身就说明它持有
  `WRITE_EXTERNAL_STORAGE` 且 **targetSdk ≤ 29**（Android 11+ 只对 targetSdk ≤ 29 保留 legacy 外部存储行为）。
  若属实，写 `Documents/` 下**不会**有权限问题。
- 但有三条不能打包票：① 微信 targetSdk 具体是多少**没有实测过**（连手机一条
  `dumpsys package com.tencent.mm | grep targetSdk` 就能定）；② Android 13+ 把
  `WRITE_EXTERNAL_STORAGE` 细分为媒体权限，写**非媒体**的 Documents 目录可能要走 SAF；
  ③ 用户若从未授予过存储权限，首次写入直接失败。
- 反过来 `Android/data/com.tencent.mm/files/` 是**微信自己的 app-specific 外部目录，永远可写、零权限**，
  代价只是 Android 11+ 文件管理器看不到（用 adb、MT 管理器可见）。

→ **稳妥做法（已写入 6.4）**：默认路径不动，加一个「用系统文件选择器授权导出目录」入口
（`ACTION_OPEN_DOCUMENT_TREE` + `takePersistableUriPermission`）。授权是授予微信 uid 的、
可持久化、重启仍有效，这样"一定能写"和"用户看得到"两者兼得，且实测结果不管怎样都不返工。
