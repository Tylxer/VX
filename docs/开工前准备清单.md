## A. 硬阻塞（不做无法开工）

### A1. 工程基座跑通 —— 目前工作区里**零代码**

现状：`2026-09-29-20-23-21\` 下只有 `docs\`，没有任何源码、没有 gradle 工程。旧项目在 `2026-09-21-19-01-19\wxgroup`（36 个 kt 文件），还没复制过来。

必须完成：
1. 复制旧项目到本工作区，**改包名** `com.v.wxgroup` → `com.lx.wxgroup`（含 `build.gradle.kts` 的 `namespace`/`applicationId`、`AndroidManifest.xml`、xposed scope 声明）
2. 一次性编译通过，产出 APK
3. `adb install` + 重启 + logcat 验证**模块确实被 LSPosed 加载**（见到模块日志）
4. 清理旧项目遗留垃圾（根目录一百多个 `*.txt` 调试文件、`output\`），补 `.gitignore`

验收标准：**能装上、logcat 有模块日志**。在此之前写任何新代码都是盲写。

风险点（旧项目已踩平，照抄即可，但要知道）：`buildToolsVersion` 必须显式 `35.0.0`、DexKit 需 `jniLibs.useLegacyPackaging = true`、xposed api 必须 `compileOnly`。

### A2. P0 锚点定位（S3 / S9 / S5）—— 需要真机 + 反编译

## C. 建议做（非阻塞，但显著降风险）

### C1. 群发风控预案（强烈建议）
全自动群发有封号风险。建议：
- 单次目标数加**硬上限**（如 200，对齐微信自带群发助手）
- 首次使用强制**小规模验证**（≤5 人）再放开
- 失败连续 N 条自动中止并提示（而不是一直重试刷接口）

### C2. 朋友圈导出路径的权限实测（建议提前验证）
`/storage/emulated/0/Android/data/com.tencent.mm/files/` 是微信自己的应用专属目录，微信进程内可写无需权限——**但 Android 11+ 上用户用文件管理器看不到 `Android/data`**，导出后取文件会很痛苦。
建议开工前实测两件事：微信能否写入、用户能否取到。若取不到，改到 `Documents/WechatXposed/moments`（需要确认微信是否持有存储权限，可能需要 SAF 授权目录树）。

### C3. 最低可运行切片（v0.1）定义
定义第一个能装能看的 APK 范围，建议：
**S3 菜单入口 + 弹窗主界面六行 + 分组管理 CRUD（含 ▲▼ 排序）+ 数据层**，不含任何 hook。
好处：最早拿到可交互产物，验证弹窗形态与 UI 选型，避免写了三千行才发现弹窗方案有问题。

### C4. 里程碑与 git 策略
- 每个可运行里程碑一个 commit，docs 与 code 分开提交
- 建议 tag：`v0.1-skeleton` / `v0.2-conv` / `v0.3-settings` / …
- 每个里程碑保留一份已知问题清单

### C5. 探针覆盖补齐
旧 7 个探针覆盖 S1（会话列表）与 S8（通讯录）。S3/S4/S5/S6/S7/S9 需要新探针或 DexKit 定位脚本。定位一次，后续换微信版本能救命（旧项目 `probe/` 就是这么留下来的）。
