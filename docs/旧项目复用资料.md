### 与当前需求的差异（必须改）

- **成员独占**：旧库是 `PRIMARY KEY (group_id, wxid)`（支持一人多组），
  我们要求「一个好友只能属于一个分组」→ 改成 `wxid` 加 UNIQUE 约束。
- **分组行排序**：我们要求分组行参与时间排序混在会话中间；旧项目的 `BAR_MODE=list`
  是否支持时间序需读 GroupBar 确认。
- **设置界面形态**：旧项目是 `EntryReceiver` + 广播（`com.v.wxgroup.action.OPEN_GROUPS`）唤起，
  我们改成微信进程内弹窗（G12）。

## 四、踩过的坑（极有价值，别重蹈）

1. **不能用 `Class.forName("com.tencent.mm.storage.r4")`** —— 走的是模块自己的 ClassLoader，
   根本看不到微信的类（实测返回 null，过滤静默退化成"全部显示"）。
   正确做法：拿一个真实的 item 对象，从它的运行时类上反射找字段。
2. **过滤后必须重映射点击位置** —— 微信的 `o2` 用位置取会话，不重映射就会「点第 3 条打开过滤前第 3 条」。
3. **ListView 的 `mDataSetObserver` 要挪到包装 Adapter 上**，否则 `notifyDataSetChanged` 不生效（`mItemCount` 不更新）。
4. **空分组要过滤成 0 条**，不能退化成"全部显示"（用户会以为筛选没生效）。
5. **DB 必须建在宿主 Context 的 filesDir**（`/data/data/com.tencent.mm/files/`）。
   模块自己包名的目录是另一个 uid，hook 代码读不到。
6. **偏好存 DB 的 kv 表，不要存 SharedPreferences** —— SP 在宿主私有目录，adb pull 不出来，出问题只能猜。
7. **DB 升级必须增量迁移**，任何 drop-recreate 都会让用户分组数据全部消失。
8. **`buildToolsVersion` 必须显式写 `35.0.0`** —— AGP 8.7.3 默认要 34.0.0，本机没装会报 "Failed to find Build Tools revision 34.0.0"。
9. **DexKit 的 so 要 `jniLibs.useLegacyPackaging = true`**，否则 Android 6+ 上不解压、运行时崩。
