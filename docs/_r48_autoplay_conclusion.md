## 一、结论（先给答案）

**「R45 的导出/解密代码直接导致滚动起播」在静态代码层面找不到任何连接点，不能成立为定案。**
R45 引入的运行时副作用**全部落在后台导出轮**，与朋友圈时间线的滚动回调、视频 view
生命周期、列表重绑没有任何源码级交集：

| R45 新增副作用 | 落点 | 能否触发起播 |
| --- | --- | --- |
| `downloadVideo` CDN 直下 | `dst.path+".tmp"`，`/sdcard/Documents/WXGroup/moments/…` | 否，模块自有目录 |
| `decryptInPlace` 原地解密 | **只改调用方传入的 tmp 副本** 前 131072 字节 | 否，不碰微信缓存 |
| 反射宿主 `MMIMAGEENCJNI` | 后台 daemon 线程，每次 newInstance + `free(handle)` | 未证（native 全局态黑盒） |
| `moments.video_decrypt=true` 默认值 | 仅作解密判据 | 否 |
| `viddec` 广播分支 | 手动探针才跑 | 否 |

全树 grep 零命中：`autoplay|startPlay|playVideo|MediaPlayer|VideoView|SurfaceView|
TextureView|onScrollStateChanged|onScrolled|addOnScrollListener`，也没有
`callMethod(...play/start/prepare/setDataSource)` ⇒ **模块从未主动起播**。
`MomentsAuto.kt`（`smoothScrollBy` 自动滚动）、`SnsGuard.kt`（DB before 钩子）
**都不在 `5358408→4ac6aae` 改动面**，是 R25 / R42 的既有代码。

⇒ 不把「R45 装包」与「滚动起播」的时间相关性写成因果性。

## 四、两条 lane 的分歧与裁决（重要，别只信一份）

反证 lane 对差分 lane 判 **「部分反驳」**，三处具体驳回：

1. **Q1⑨ 把 R44 探针整族判「无运行时副作用」是排除过度**：那是「R46 归档后的仓库态」
   ≠「R44/R45 期间设备装包态」；「Route C 对导出目标多余 / 当时三轮未落盘」是目标层与
   单次实验层结论，不等于该代码路径从未在宿主进程产生副作用。
2. **Q3「路径不相交」漏了 `SnsDispatchProbe.snsRoots()`**：它只核对了 R45 `MomentsExport`
   写 `/sdcard/Documents/WXGroup/moments/`，没覆盖 `cache/<hash>/sns/` 这套微信播放器
   自己读的路径 ⇒ 「CDN 预热 / 共享缓存」应从 `排除` 降为 `UNCERTAIN`。
3. **Q5 把 Q1 自己标了 UNCERTAIN 的 native 全局态收成定案**；且 `SnsVideoDecProbe.kt:32-33`
   的 KDoc「全是实例方法」与 `.workbuddy/memory/2026-11-08.md` 的「全是 static native」
   **互斥**，静态不可判。

同意部分：`auto_export` 不改变 `x2(256)` / `pokeExport` / 自动滚动的频率或触发条件；
模块无播放/滚动 API（独立 grep 复核）。仅更正措辞：导出轮**调度在主线程 Handler、
执行体在 daemon**。

4. **清微信 `sight_*` 缓存 → 复现**：消失 ⇒ H-B 坐实；且现象应**集中在名单好友 /

5. **时间戳对齐**：`logclear` → 复现滚动 → 拉 LogX 环形日志（5000 行会被 `K7 perf`
   每 250ms 一条刷掉，必须测前清），对齐 `MOMENT refresh bg-sent` / `MOMENT autoload` /
   `MOMENT export` / `VIDDEC inplace` 与起播时刻。无稳定先后 ⇒ H-C 判死。
6. **微信侧黑盒**：播放器侧 hook / 文件访问日志，确认微信是否打开过
   `/sdcard/Documents/WXGroup/moments/…/vid_*.mp4`；以及 `MMIMAGEENCJNI` 是实例态还是
   静态全局（解 KDoc 与 memory 的互斥）。
