# 转发选人器缺「文件传输助手」— 成因锁定与修复（2026-11-28 20:4x）

> 结论：**成因 B（exclude 自排除），非数据源缺口**。Pro 402 降档 Lite 查证 + 主会话亲核；真机 A/B 已锁定成因，方案由用户拍板。

## 1. 现象与成因（真机取证）

- 用户报障：在昵称「文件传输助手」会话里选「转发（模块）」，选人器里没有「文件传输助手」，无法转回自己。
- **A/B 区分（20:4x，用户实测）**：从昵称「测试群聊」转发时，选人器里**有**「文件传输助手」。⇒ 数据源正常（`friend_cache` 有 filehelper）、白名单有效（`ForwardLogic.pickerFriends` 放行 `wxid=="filehelper"`）。
- **根因**：`ForceForward.kt:1863` 旧代码 `exclude = setOf(sourceChat)`；从文件传输助手转发时 `sourceChat = "filehelper"`，`PickerFriends` 的 `f.wxid !in exclude` + `resolveTargets` 的 `add(..., exclude)` 双重把它排掉。旧注释写「转发回原会话没意义」是设计意图，与用户诉求冲突。
- 排除成因 A 的铁证：`op=who --val filehelper` → `WHO filehelper nick=文件传输助手`（rcontact 有此行）；从测试群聊转发能看到 ⇒ friend_cache 也有。

## 2. 用户拍板

「所有会话都允许转回自己」⇒ 取消 exclude 机制（非只破例文件传输助手）。

## 3. 改动（最小步）

| 文件 | 改动 |
|---|---|
| `feature/ForceForward.kt` `openTargetPicker` | `exclude = setOf(sourceChat)` → `emptySet<String>()`；KDoc 同步；日志 `exclude=none source=...` |
| `feature/ForwardPicker.kt` | exclude 入参 KDoc 同步（纯函数语义保留、主入口恒传空集） |
| `ForwardLogic.pickerFriends` / `resolveTargets` | **不动**：exclude 纯函数语义与 6 条既有单测全保留 |

**安全点**：`resolveTargets` 的去重靠 `LinkedHashSet`（`:280`），与 exclude 无关 ⇒ 传空集不破坏「分组/标签展开同人不重复」。

**发送通路**：`execute → runBatch(snap, plan, targets)` 通用 wxid 列表；`TextSender.kt:24-26` 有 `op=send sub=test --es val filehelper` 真实投递成功实证（message 表 type=1 isSend=1）⇒ 选中 filehelper 能真发出去。

## 4. 三档红线（R42-N1N6）

- **进入边界**：任意会话（群聊/单聊/文件传输助手）点「转发（模块）」都进选人器，且不再自排除；`exclude` 恒空。
- **返回边界**：选中自己后能转发成功、消息出现在目标会话；选人器其他项（好友/群聊/分组/标签）行为不变。
- **复位边界**：取消/退出选人器不残留勾选状态（Panel.pop + selected 是实例字段，退出即弃）；转回自己不影响其他转发场景；分组/标签展开去重仍靠 LinkedHashSet；关掉模块后行为回原生。
