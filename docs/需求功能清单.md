# 微信好友分组 LSPosed 模块 — 需求功能清单 v5.19

目标环境：微信 8.0.48（谷歌 Play 版） · LSPosed 2.0.1 (7639) · JDK 21 + SDK 34
包名：`com.tencent.mm` · 模块包名暂定 `com.lx.wxgroup`

---

## 一、产品形态（已锁定）

会话列表里，分组行就是**列表中的普通一行**：与会话行等高、跟列表一起上下滚动、会被滑走。
点击分组行 → 右滑进入二级分组页，二级页复用微信会话行的渲染，只是数据源换成该分组成员。

## 五、D. 配置界面（微信进程内弹窗 UI）

> **实现方式变更（v5.9，由 G12 弹窗形态推导）**
> - D 部分不再写成"模块 APK 的独立 Activity"，改为**微信进程内的 UI**（Dialog / PopupWindow / 覆盖层）
> - **不提供 launcher 图标**，模块在桌面上不可见，唯一入口是微信右上角「+」菜单
> - 连带简化：D3/D4 那套"配置界面发广播 → 微信进程 receiver 唤起选择界面"的**跨进程链路不再需要**
>   ——弹窗本就运行在微信进程内，可直接启动微信原生「标签 → 添加成员」选择界面
> - 附带影响：LSPosed 管理器里的"打开模块 UI"按钮将不可用（因为没有可启动的入口 Activity）

> **与「防止消息撤回」的依赖关系**：「显示撤回提示」只在消息**确实撤回成功**时才有可见效果。
> 当「防止消息撤回」开启时，撤回被拦截、原文保留，不会产生撤回提示，此时本开关无实际作用。
> 本开关真正生效的两个场景：①「防止消息撤回」关闭时；② 模块启用之前就已留在聊天记录里的
> **历史撤回提示**——即"关闭后连历史提示也一并隐藏"要覆盖的情况。

> **作用域：整个防撤回功能域只作用于他人的消息，自己的消息完全不受影响。**
> 自己撤回自己的消息照常成功；自己的撤回提示「你撤回了一条消息」也照常显示，
> 不受本页任何开关控制（包括「显示撤回提示」关闭时依然可见）。

> ⚠️ **全自动的风险（已提示，用户确认采用）**
>
> 自动短时间向大量会话发消息是微信重点检测的行为，可能导致**发送功能被限制**或**账号被封**。
> 缓解手段已内置：随机间隔（0 ~ 设定值）、目标去重、可随时暂停/结束。
> 另需知道：微信自带「群发助手」（设置 → 通用 → 辅助功能）官方支持一次发给 200 人，
> 本模块的价值在于**可按自己的分组/标签组合发送**，不是替代官方功能的唯一途径。

## 九、开工前必须落实的技术前提

反编译微信 8.0.48 APK 后需确认以下类名（决定 F2 与全部 hook 可行性）：

1. 会话列表 Adapter 类（及 `getCount` / `getView` / `getItem` / `getItemViewType`）
2. 会话 item 的 layout 资源名（二级页要复用同一渲染）
3. 会话列表点击回调（onItemClick）与长按菜单入口
4. 会话对象的 username / 昵称 / 摘要 / 时间 / 未读数字段，以及**头像加载接口**（A4-a 需要）
5. 置顶会话的判定字段（用于 A13 定位置顶区边界）
6. 微信原生「标签 → 添加成员」选择界面的类名与其「确定」回调（D3/D4）
7. 标记已读 / 删除会话 / 置顶会话 的调用入口（B7、A7）
8. **右上角「+」下拉菜单的实现类与菜单数据源**（G1，需确认是 `MMListPopupWindow` 还是自定义 PopupWindow）
9. **撤回消息的处理入口**（防撤回功能域）
10. **朋友圈数据接口**：动态拉取与刷新、动态/评论的删除标记（防撤回 + 朋友圈域都要）
11. **红包领取界面（拆红包页）的「拆红包 / 领取」按钮**（红包域：不 hook 消息接收，只在领取界面出现后自动点击该按钮）
12. **双击头像触发拍一拍的手势处理入口**（聊天域 · 禁用双击拍一拍）
13. **消息列表渲染入口**：防撤回需要在撤回提示消息的生命周期里替换内容；且「显示撤回提示」关闭时，要能在渲染阶段过滤掉**历史已存在**的撤回提示消息（不只是拦新的）
14. **被 @ 时的响铃与震动入口**（聊天域 · 防止被@）：只需拦住「收到 @ 我的消息 → 播放提示音 / 触发震动」这一个点。
    **不要动**角标、消息渲染、通知栏 —— 「[有人@我]」标记与消息本体必须保持微信原样。
    需要能识别「这条消息 @ 了我」以及「来自哪个群」（用于查允许/排除名单）
15. **微信电话（语音 / 视频来电）的判定**（聊天域 · 免打扰）：必须能区分「普通消息通知」与「微信来电」，
    前者掐声音震动、后者**照常响铃振动**。两者在微信里走的是不同链路，需要分别定位
16. **群发相关三处**（群发域）：① 微信自带标签的读取 —— `field_contactLabelIds` 已有锚点（只读），
    但还缺「标签 id → 标签名」映射与「标签 → 成员列表」；
    ② **底层「发送消息」接口（v5.15 起为强制项）**：因为群发必须全程后台、不打开聊天界面，
    **不能再退回到"打开聊天页 + 点击发送按钮"的方案** —— 那条路必然抢前台。
    必须找到不依赖 UI 的发送入口（例如消息发送/存储相关的 service 方法）；
    ③ 发送结果的成功 / 失败判定，用于推进与重试（后台场景拿不到 UI 反馈，只能靠接口返回值或数据库落库情况判断）
17. **强制转发相关四处**（强制转发域）：① **聊天页长按消息菜单的构建入口**
    （**无论该消息微信是否已提供「转发」，都要追加一项**，菜单中允许出现两个「转发」）；
    ② **微信原生转发链路的调用入口**（传入 msgId 与目标 talker），用于保留「转发」标记的方案一；
    ③ **消息内容与资源的提取**（文本、图片 / 视频 / 语音的本地文件路径），用于降级重发；
    ④ 降级重发复用第 16 项的**底层发送接口**（与群发域共用）
18. **新加群自动免打扰相关四处**（聊天域）：① **「加入群聊」事件的 hook 入口**（被邀请 / 扫码进群等，
    进群瞬间触发，是本功能的触发点，也是最大的未知数）；② **群信息里的群主字段**（roomowner 之类），
    用于判定"自己创建的群"；③ **群「消息免打扰」的设置接口**（设置微信该群自带的免打扰开关）；
    ④ **自身 wxid 的获取**（与群主字段比对）

获取方式：手机连 USB 授权调试后 `adb shell pm path com.tencent.mm` 拉取 APK 反编译。
