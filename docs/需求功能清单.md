### 三处重复是怎么合并的

**① 静音逻辑三合一（K9）** —— 防止被@、免打扰时段、微信来电放行，这三者要拦的是**同一个点**：「收到消息 → 播放提示音 / 触发震动」。如果各写各的，三个 hook 会抢同一个入口、互相覆盖，最坏情况是免打扰把微信电话也掐了。合并成一个判定函数：

```
if (是微信来电)            → 放行（照常响铃振动）
else if (免打扰时段已开启 && 当前在时段内) → 静音
else if (防止被@已开启 && 这条@了我 && 群在作用域) → 静音
else                      → 保持微信原样
```

作用域判定：先查排除名单（命中则不生效），再看允许名单。

**② 选择器七处合一（K3）** —— 群发目标、转发目标、防@允许名单、防@排除名单、朋友圈导出名单、加入分组、添加成员，以前是七个各自要做的页面，现在是一个组件三个参数搞定。差异只在：数据源（好友·群·分组·标签）、单选还是多选、能不能新建。

**③ 设置页共用渲染器（K2）** —— 五个二级页加起来 20 多个设置项，控件只有 5 种。渲染器统一负责画和存，加一个新开关只需加一行配置，不用碰 UI 和备份代码。

## 二、数据层（合并后的表）

| 表 | 字段 | 说明 |
|---|---|---|
| `groups` | id / name / sort_order / pinned / created_at | 分组。`sort_order` 由**分组管理页手动拖拽**写入（松手即存），不使用按名称/时间的固定排序 |
| `group_members` | id / group_id / username / display_name / type / added_at | **username 上加 UNIQUE 约束**，数据库层面强制"一个好友只能属于一个分组"（旧库是 `PRIMARY KEY(group_id, wxid)`，允许一人多组，必须改） |
| `auto_dnd_done` | chatroom_id（主键）/ handled_at | 已自动设过免打扰的群，用于"只设一次、手动关掉后不再自动打开" |
| `kv` | key / value | 全部开关与数值。配置项处理规则：导入时只覆盖备份里存在的项 |
| `friend_cache` | username / nickname / avatar / updated_at | 好友与群名缓存，供 K3 选择器与 K10 取数使用 |

约定：主键一律用 username（wxid / chatroom id），**不用昵称**（昵称会改、会重名）；分组活跃时间运行时算，不落库；只在微信主进程打开 DB（避开 `:push` / `:tools`）；DB 建在宿主 `filesDir`；**升级必须增量迁移**（drop-recreate 会让用户分组数据全没）；配置**不存 SharedPreferences**（在宿主私有目录，adb pull 不出来，出问题只能猜）。

## 五、D + G. 模块入口与设置弹窗

形态（v5.9 由 G12 推导）：UI 全部是**微信进程内的弹窗**，不是模块 APK 的独立 Activity；**不提供 launcher 图标**，唯一入口是微信右上角「+」菜单。

- 好处：弹窗本就在微信进程内，可直接读会话数据与头像，**跨进程链路不再需要**（原 D4 的广播 → receiver 方案作废）
- 代价：LSPosed 管理器里的"打开模块 UI"按钮不可用（没有可启动的入口 Activity）

## 六、功能域

### 6.1 聊天

| 项 | 说明 | 控件 |
|---|---|---|
| 分组管理 | 置于本页顶部 → 分组列表页 → 成员页 | 进入 |
| 启用分组行 | 好友分组功能总开关 | 开关 |
| 显示未读 | 分组行是否显示未读角标 | 开关 |
| 关闭拍一拍 | **禁用双击头像触发拍一拍** | 开关 |
| 开启防止被@ | 被 @ 时**没有提示音、没有震动**；其他保持微信原样（「[有人@我]」标记照常显示、消息照常收到） | 开关 |
| 设置允许名单 / 设置排除名单 | 名单内容是**群**，走 K3 选择器（多选） | 进入 |
| 名单优先级 | **排除名单优先**：命中排除名单的直接不生效，再看允许名单 | 规则 |
| 免打扰 / 开始时间 / 结束时间 | 时段内**除微信电话外**所有提示音和震动都掐断；角标、消息、通知栏保持原样；**支持跨天**（23:00 → 次日 07:00） | 开关 + 时间 |
| 新加群自动免打扰 | **除自己创建的群外**，进入任何新群聊自动打开该群的微信自带「消息免打扰」 | 开关 |

**「新加群自动免打扰」的四条判定**：新群 = hook 进群事件（被邀请 / 扫码进群，进群瞬间设置）；自建群 = 群主是自己（读群主字段与自身 wxid 比对）；存量群 = **只管新加的**（开关生效前就在的群不动）；手动关掉后 **不会再自动打开**。

> ⚠️ 进群事件不一定有稳定 hook 点，定位不到会**漏设**。备选退路：改为定期扫描群列表补设。
> 另外它与「免打扰时段」是**两个独立维度**（一个是按群开关微信自带免打扰，一个是全局按时段静音）。

### 6.2 防撤回（控件全为开关）

| 项 | 说明 |
|---|---|
| 防止消息撤回 | 拦截聊天消息撤回（**仅他人的消息**） |
| 防止朋友圈动态撤回 | 拦截朋友圈动态被删除 |
| 显示朋友圈动态[已删除]标签 | 已删动态加标签 |
| 防止评论撤回 | 拦截朋友圈评论撤回 |
| 显示朋友圈评论[已删除]标签 | 已删评论加标签 |
| 显示撤回提示 | **关闭时，连历史已存在的撤回提示一并隐藏**，不只是拦新的；只对他人撤回产生的提示生效 |

> **作用域**：整个域只作用于他人的消息。自己撤回照常成功，自己的「你撤回了一条消息」照常显示，不受任何开关影响。
> **依赖关系**：「显示撤回提示」只在撤回确实成功时才有可见效果；「防止消息撤回」开启时不产生撤回提示，本开关此时无实际作用。真正生效的场景是：① 防止消息撤回关闭时；② 模块启用前就留在记录里的历史提示。

| 执行方式 | **全自动 + 全程后台**：不打开聊天界面、不跳转、不抢前台，用户可照常使用微信 |
| 发送中页 | 进度 `n / 总数`、当前对象、进度条、**自动逐条推进**、「暂停」「结束」 |
| 进度提示 | **只重开弹窗可见**：后台期间无任何前台提示（无通知、无悬浮窗、无角标） |
| 目标去重 | 同一人被多个分组 / 标签选中时只发一次 |

> ⚠️ 全自动群发的风控风险已提示并确认采用。缓解：随机间隔、目标去重、可随时暂停结束。
> 微信自带「群发助手」支持一次 200 人，本功能的价值在于**可按自己的分组 / 标签组合发送**。

### 6.6 强制转发

| 项 | 说明 |
|---|---|
| 入口 | 聊天页**长按任意一条消息**的菜单 |
| 触发条件 | **一律追加，允许重复**：微信已有原生转发时也照样追加，菜单里出现两个「转发」（黑色原生 + 绿色模块，带「模块」角标） |
| 覆盖类型 | **正常聊天记录**：文本 / 图片 / 视频 / 语音 / 文件 / 名片 / 位置 / 链接 |
| 实现方式 | **混合降级**：① 先走微信原生转发链路（保留「转发」标记）；② 被拒则降级为内容重发（取出文本或本地文件用 K8 发送），对方能收到但无转发标记 |
| 转发目标 | K3 选择器，三 Tab（好友·群聊 / 模块分组 / 微信标签），可多选批量转发 |
| 开关 | **不加开关，默认常开** |
| 目标去重 | 沿用群发规则 |

> 允许重复的理由：模块转发的价值不在"能不能转发"，而在**目标可批量勾选**（分组 / 标签 / 好友），这是原生转发做不到的。
> ⚠️ 技术不确定性：原生转发入口是否接受模块构造的请求（msgId + 目标 talker）需实测。覆盖类型收窄后降级触发概率低，只是兜底。

### 6.7 备份

| 项 | 说明 |
|---|---|
| 导出 / 导入 | 「备份」二级页两行 |
| 存放位置 | **系统文件选择器（SAF）**，导出自己选目录与文件名；导入可从任意位置选 |
| 分组冲突 | **成员取并集**，两边合并去重。⚠️ 因成员独占，被并入的成员会从原分组自动移出 |
| 配置项 | **只覆盖备份里存在的项**，没写的保持当前值 |

备份范围 = 模块配置（kv 全表）+ 分组设置（groups + group_members）。
