## 本轮踩的坑（值得记）

### ⛔ `adb shell` 会把参数**再解析一次**

设 JSON 数组目标时：

```bash
adb shell "am broadcast ... --es val [\"a\",\"b\"] -p com.tencent.mm"
# ⇒ 实际写入的是  d         ← 方括号和引号被设备端 sh 吞掉
```

原因：`adb shell` 把后续参数拼成**一个字符串**，在设备上用 `/system/bin/sh -c` 执行，
即使 Python 侧用 `subprocess` 传的是参数列表（`_lib.sh` 就是这么写的）**也躲不掉**。

✅ **正确写法**：给值**再包一层单引号**（sh 单引号内是字面量）：

```python
val = "'" + '["a","b"]' + "'"          # => 设备端收到 --es val '["a","b"]'
_lib.sh('shell','am','broadcast',...,'--es','val',val,'-p','com.tencent.mm')
```

✅ 中文同理：`'【模块自检】群发链路验证，可忽略'` 加单引号后完整写入（已 `kvget` 复核）。

⚠️ 判据：**写入后必须 `kvget` 回读复核**，别只看 `kvset` 的回显。
第一次我用裸数组，回显看着像成功了，回读才发现是 `d`。

### ⛔ 关键：光改默认值救不了老用户

`Kv.getString(MOMENTS_EXPORT_PATH)` 读的是**库里的持久化值**，`ifBlank { DEFAULT }` 只兜空串。
老用户 kv 表里存着旧路径 ⇒ 默认值怎么改都不会被用到，导出继续落在用户看不见的地方，**且静默**。
所以必须有 `isLegacyExportPath` 判定 + `Kv.putString` 写回（写回是必须的：只在内存换，
下次 `refresh()` 又读回旧值，每 3 秒重做一次迁移）。

### 判定口径（用户自己选过的路径一律尊重）

- 空串 / null → 不迁移（走 `ifBlank` 兜底）
- 恰好等于旧默认值，或在其**子路径**下 → 迁移
- 任何其他路径（含 `MyMoments`、SD 卡、**别的 app 的 Android/data**）→ 不迁移
- `.../moments2`（旧根的兄弟目录）→ **不**迁移 ← 专门防 `startsWith` 少写斜杠
