先把 Dalvik 两条指令的语义钉死（这是前面所有错误的根）：

门控真代码（`r5.j` 的 `0183`~`0190`）：

```
0183  iget-object v4, v1, Ljj/k0;.field_appId   ; v4 = appInfo.field_appId
0187  o.f(v4, "field_appId")                    ; Kotlin 非空断言
018a  if-nez v2, 0190     ; ★ p7 != 0  → 跳 0190【保留 appId】
```

## 问题 1 · 搜索框拿得到焦点但 IME 不弹 —— 根因已锁定

### 实测证据链（设备在线，wxgroup APP 已装 01:34 版本）

| 步骤 | 命令 | 结果 |
|---|---|---|
| 进到 PickerPage | UI 点 分组模块→群发→选择发送目标 | `PICKER: True \| 搜索: True` |
| 找 EditText | `uiautomator dump` | `<node class="android.widget.EditText" focusable="true" focused="false" bounds="[150,734][1290,804]" hint="搜索" />` |
| **点它** | `input tap 720 769` | **`focused="true"`** ← 焦点**拿到了** |
| IME 服务状态 | `dumpsys input_method` | **`mInputShown=false`**、`mIsInputViewShown=true` |
| 微信 IME client | `dumpsys input_method` 取 `mUid=10363` 的 ClientState | **`sessionRequested=false`、`curSession=null`** |
| **Dialog 窗口 flags** | `dumpsys window windows` 取 `Window{d2b97fb u0 群发}` | **`fl=DIM_BEHIND ALT_FOCUSABLE_IM SPLIT_TOUCH HARDWARE_ACCELERATED`** |

### 根因

⭐ **`FLAG_ALT_FOCUSABLE_IM`**。AOSP 语义：窗口带这个 flag ⇒ 进入「替代焦点模式」，
**IME 不会被自动拉起**（框架认为这个窗口不需要文字输入，典型是模态确认框）。
`AlertDialog` 骨架**默认就带它**，而 `Panel` 的搜索框长在这个 Dialog 里 ⇒ 恒不弹。

⚠️ 这不是「`requestFocus` 没调」：焦点**已经拿到了**（`focused=true`），
所以任何「补 `requestFocus()` / 补 `showSoftInput()`」的改法都是**治错方向**。
前者已经成立；后者在 `ALT_FOCUSABLE_IM` 下会被系统丢弃（`sessionRequested` 始终 false 是证据）。

### 已排除的方向（别再往这查）

- ❌ `PickerPage` 少写了 `requestFocus` —— 实测 `focused=true`，不成立
- ❌ `SOFT_INPUT_ADJUST_RESIZE` 没设 —— `mAttrs` 里 `sim={adjust=resize}` **已生效**（`UiKit.widen` 起作用了）
- ❌ 输入法本身坏了 —— 同一台机器 `mIsInputViewShown=true`，输入法窗口 `Window{59c4c00 u0 InputMethod}` 存在
- ❌ ListView 抢焦点 —— 焦点在 EditText 上（`mServedView` 是微信自己的 `MMEditText`，那是宿主的另一个输入框，与本 Dialog 无关）

### 修复方案（Flash 级，判据已定死）

1. 在 `Panel.openInternal()` 里 `d.create()` 之后、`show()` 之前：
   `d.window?.clearFlags(WindowManager.LayoutParams.FLAG_ALT_FOCUSABLE_IM)`
2. 同时给搜索框补 `showSoftInput` 兜底（**只在 clearFlags 之后有意义**）：
   点 `EditText` 时主动 `InputMethodManager.showSoftInput(view, 0)`。
   放 `PickerPage` / `BatchPicker` / `ForwardPicker` / `GroupDetailPage` 四处共用一个 `UiKit` 助手。

⚠️ **判据（真机）**：点搜索框后 `dumpsys input_method` 的 `sessionRequested=true` 且 `mInputShown=true`。
**不算判据的**：「看起来弹了」（截图不可靠）、`focused=true`（改之前就已经是 true）。

⚠️ **回归风险**：`ALT_FOCUSABLE_IM` 一清，**所有** Panel 页面都受影响（不只搜索框）。
须确认：① 返回键仍然只走 `pop()` 不误触 IME 收起 ② 没有输入框的页面行为不变
③ `UiKit.input`（新建分组）本来就弹不出，清完 flag 后要变正常（这是顺带修的）。
